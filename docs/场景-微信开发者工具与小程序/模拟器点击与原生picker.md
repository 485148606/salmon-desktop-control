### 0.5.5.1 微信开发者工具的模拟器：第一次点击会被吞

- 模拟器（右半屏那个手机预览）里的按钮/tabBar，**第一次点击经常不生效，要点第二下才响应**。连着试了两轮都是这个规律。
- 现象：`click` 返回 ok、坐标也对，页面就是不动；再点一次立刻切页/弹层。
- 对策：**对模拟器里的元素一律连点两次**（间隔 ~1s），或把 click 写进单进程闭环时直接发两发。
- 这是模拟器/窗口激活层面的问题，**不是被测小程序代码的 bug** —— 别看到点不动就去改业务代码。
- 另：DevTools 的窗口标题 = 项目名（来自 `project.config.json` 或优先级更高的 `project.private.config.json` 的 `projectname`），用它 `win-list --keyword <项目名>` 找窗口最准。
- **切换型（toggle）按钮千万不能"连点两次"**：模拟器虽然会吞第一下，但像"添加租赁"这种 `bindtap` 里做 `open = !open` 的折叠开关，**双击 = 开一次又关一次，看起来完全没反应**。对策：**先单击一下，截图确认；没开再补一下**，别无脑双击。（2026-09-15 实测：双击"添加租赁"白折腾两轮。）
- **原生 picker 的滚轮（date / selector 的月-日-年列）脚本驱动不了**：点开 picker 没问题（`取消/确定` 也能点），但列里的`滚轮`对 `scroll`（滚轮事件）和 `drag`（拖拽）**都不响应**，日期始终停在原值。要验联动逻辑别在模拟器里搓 picker —— 改用 node+vm 直接加载 Page 配置跑断言（见下）。
- **验业务联动逻辑，正解是"脱 UI 单测"**：把页面 js 用 `vm` 加载、注入假 `wx`/`Page`，实现一个 `setData`，然后直接调 `onXxxChange({detail:{value:...}})` 断言结果状态。秒级、可重复、不受 picker 限制 —— 比在模拟器里盲点可靠得多。
- ✅ **反过来：小程序里"自定义组件"（自己写的 view 弹层，不是原生 picker）在模拟器里点击完全正常**，可以放心用脚本驱动、逐屏截图验收。所以"验不了"只针对原生 picker 滚轮；自定义 UI 该点就点。
- ⚠️ **"打开弹层"的入口行千万别双击**：模拟器虽爱吞第一下，但第一下若已打开弹层，第二下就落在**遮罩**上，会立刻把弹层关掉（表现为"点了没反应"）。对策与 toggle 同：**先单击 → 截图确认 → 没反应再补一下**。
- 🚨 **弹层/底部区域的按钮坐标，一律用 `locate-text` 拿 OCR 坐标，别靠截图目测估**（2026-09-15 实测翻车）：底部弹层里"租相机"按钮，肉眼估 y=1591，OCR 实测中心在 **y=1525** —— 差 66px，正好点在下方的留白上，白折腾五六轮还一度误判成"showModal 或 catchtap 有 bug"。元素密集 + 大留白的区域（底部弹层、列表卡片）目测误差可达 60~70px。
  ```bash
  "$PY" "$MC" locate-text --text 租相机 --region 2100,1450,780,260   # 先拿准确坐标
  "$PY" "$MC" click --x 2471 --y 1525
  ```
- ⚠️ **每次 `click` 之前都要先 `win-activate`**：只 `win-move` 把 WorkBuddy 挪走还不够，目标窗口没被激活时点击可能落到别处（实测同一坐标"有时灵有时不灵"就是这个原因）。
- 🔄 **WorkBuddy 主窗口会换句柄**（进程重启后 hwnd 就变了，实测从 198964 → 197468）。旧句柄调 `win-move` 会直接返回 `ok:false`（width/height=0）。**每次开工前先 `win-list --keyword WorkBuddy` 重新取句柄**，别硬编码。
- 🐞 **`mc.py type --text "纯数字"` 曾经必然失败（v1.22.2 已修）**：`mc.py` 的 `_coerce()` 把纯数字字符串转成了 int（`"0"`/`"1"` 还会转成 bool），于是 `pyperclip.copy(int)` 抛异常 → 回退 `pyautogui.write(int)` 报 `TypeError: 'int' object is not iterable`。**症状：能给中文打字，但输手机号/验证码/金额必挂**。
  修法：`mc.py` 里新增 `STR_KEYS = {text, json, out, template, title, subtitle, keyword, note}`，这些 key 的值**原样保持字符串**；`svc.py::op_type` 再加兜底 `str(text)`。备份 `*.bak_before_strkey_fix_20260915`。
  **自查一行**：`python -c "import mc; print(repr(mc.parse_argv(['type','--text','13900002222'])[1]['text']))"` 应输出 `'13900002222'`（带引号）。
- 🚫 **不要把 `--text` 的值当成"能自动识别类型"的参数**：其它以文本为语义的 key（`--keyword`、`--out`、`--template`）同理，已一并放进 `STR_KEYS`。

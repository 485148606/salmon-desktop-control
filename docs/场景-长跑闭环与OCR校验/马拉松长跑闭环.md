## 🛠 v1.2.1 第 6 轮（2026-09-08）：1h23m 马拉松实测 1531 轮闭环 + 修复

**实测成绩**（22:37→00:00，6 轮长跑 1531 次"type→PrintWindow 截图→OCR 验证"闭环）：type 1531/1531（100%）、shot 100%、match 99.4%（未匹配为截图晚一帧时序问题，非操作失败；末轮 v6 450 次 100% 全中）。

**代码变更**（svc.py/mc.py 均已改，改后需重启 svc 生效——`mc.py` 下一条命令会自动拉起新进程）：
1. **mc.py UnboundLocalError 根治**：main() 内冗余 `import urllib`（原行 286）把 urllib 遮蔽为函数局部变量 → 所有 HTTP 报错场景（--help/monitors/wait-text 报错）Traceback。删除该行后报错全部友好返回 JSON。备份 `mc.py.bak_20260907`。
2. **svc.py win-list 缺 pid 字段**：268 窗口 pid 全 None。窗口枚举输出补 `"pid"`，现返回真实 PID（v6 长跑 22 次检查全通过）。备份 `svc.py.bak_20260907`。
3. **svc.py 新增 `monitors` op**：此前 mc.py/screen.py 支持但 svc 报 unknown op（架构不一致）。现在 `mc.py monitors` 返回全部显示器几何 + DPI scale（实测 scale 2.5）。
4. **svc.py `wake` 升级 SendInput**：实测 DPMS 显示器睡眠下 pyautogui 移鼠标 / keybd_event / mouse_event / SC_MONITORPOWER 广播**全部无效**，唯 **SendInput 硬件级按键（F15+Space+A）有效**（23:21 实测突破）。wake 现按 SendInput 优先 + SetThreadExecutionState 防再睡 + pyautogui 兜底执行，返回 `method:"SendInput"`。

**新增实测经验（写进排障）**：
- 显示器睡眠 ≠ 窗口坏：mss shot/color 全黑是环境现象，先 `wake`，仍黑用 `shot-pw`（PrintWindow 不受影响）。
- find 找不到先查两件事：屏幕醒着吗？模板与屏幕**同源**吗（别拿 PrintWindow 逻辑像素图当模板去物理屏找，跨 2.5× DPI 会失配）？
- type 无 1000 字符硬限（实测 2000 单次成功）；"截断"假象 = 后台长跑并发抢剪贴板。8 种语言/代码字符全支持。
- wait-text 单发稳定（45 次 0.3-10s 全 OK）；**≤0.3s 高频轰炸会触发 svc 连接重置**（svc 单线程串行），间隔 ≥1s。
- batch 不支持嵌套 wait-text/wait-stable/wait-text-gone（子步含 wait 会 RST）；wait 类单独一条命令。
- svc 换 PID / `_svc_booted:true` = 自愈设计（串行锁 + 300s 看门狗 + mc.py 自动拉起），非随机崩溃，看到别慌。
